# Why I'm Learning Data Science When AI Can Already Do the Work

*My first steps into data science, a little skepticism about learning Python, and figuring out where humans fit into an AI-driven world.*

I've recently decided that I want to learn data science. Python, SQL, statistics, machine learning, the whole nine yards. Sounds exciting, right?

Well, there's one little problem. I'm struggling to convince myself that spending the next year learning Python and SQL is the best use of my time when AI can already write code faster than I probably ever will. And that's assuming I actually become good at programming. 😂

I'm not completely new to technology. I've spent years working in IT and cybersecurity, and these days I work in community management within the cybersecurity industry. I've been around enough technology to understand how quickly things change. But I'm also not a programmer or mathematician. Math has never been my strongest subject, and the idea of sitting through hundreds of hours of programming tutorials isn't exactly getting me out of bed in the morning. Especially when I can open ChatGPT, explain what I want, and have it generate a working Python script in seconds.

So that got me thinking. **Am I approaching this whole data science thing the wrong way?**

## Why Learn Something AI Can Already Do?

Let's say I spend the next year learning Python. I work through tutorials, build projects, learn SQL, and eventually get comfortable writing code without constantly Googling everything. Great! I've accomplished something. But where will AI be a year from now?

Right now, AI can generate complex Python scripts, write SQL queries, build visualizations, and even help train machine learning models. It can accomplish in minutes what might take me hours, and that's before considering how much better these systems are likely to become. So why would I spend all that time trying to compete?

I'm not saying Python or SQL are useless. Far from it. Understanding how code works is still important, especially when you need to figure out why something isn't working. But I am questioning whether **becoming an expert programmer should be the goal, or whether programming should simply be one of the tools I learn to use.**

There's a pretty big difference between those two things. I don't necessarily need to memorize every Python function or become someone who can write thousands of lines of code from memory. I need to understand what the code is doing, why it's doing it, and whether the results make sense.

## AI Is Really Good at Doing Things. Even When It Shouldn't.

One thing I've noticed while working with AI is that it really, really wants to be helpful. Sometimes a little too helpful.

Ask it to fix a problem in your code, and it might rewrite three other things that were working perfectly fine. Ask it to improve something, and suddenly you've got an entirely different implementation. Thanks, I guess? 😂

And apparently, this isn't just something I've experienced.

A 2026 research paper titled **"Coding Agents Don't Know When to Act"** examined how AI coding agents respond to software issues that have already been resolved. The researchers created a benchmark of 200 human-verified tasks where no code changes were necessary and tested five models across four agent setups.

The results? **Even advanced AI coding agents proposed unnecessary changes in 35% to 65% of cases.**

Think about that for a second. The correct solution was to do absolutely nothing, and the AI still wanted to change things. The researchers described this as an *action bias*, where AI agents tend to take action even when doing nothing would be the better decision.

[Read the research: Coding Agents Don't Know When to Act](https://arxiv.org/abs/2605.07769)

Now, this doesn't mean AI is bad at programming. The study examined a specific set of coding tasks, not every possible programming situation. But it does highlight something important. **Just because AI can produce an answer doesn't mean it knows whether that answer was necessary in the first place.**

And I wonder how often that same problem shows up in data analysis. What happens when AI finds a pattern in a dataset that isn't actually meaningful? What happens when it uses incomplete data, makes an assumption, or confidently presents a conclusion that isn't supported by the evidence? If I don't understand data science myself, how would I even know?

## Maybe I Need to Learn How to Think Like a Data Scientist

This is where my perspective on learning has started to change. Instead of focusing entirely on how to write Python or SQL, I want to focus on learning how a data scientist actually thinks.

And no, I don't mean opening ChatGPT and typing: *"You're an expert data scientist with 20 years of experience. Analyze this data."*

Congratulations. You've now given your AI an imaginary résumé. 😂

I'm sure that kind of prompting can help provide direction, but it doesn't magically guarantee that the AI will approach the problem correctly. It doesn't know everything about the business, the people involved, how the data was collected, or what might be missing unless that information is available to it. And even when it has all that context, it can still make mistakes.

I want to learn how to ask better questions. Not just "What does this data tell me?" but questions like:

- Where did this data come from, and can I trust it?
- Are we measuring the right things?
- Is there information missing that could completely change the conclusion?
- Does this relationship actually mean something, or is it just a coincidence?
- Are we confusing correlation with causation?
- What assumptions are being made?
- If I make a decision based on this analysis, what happens if it's wrong?

These are the kinds of questions I want to become comfortable asking. Because there's a difference between having information and actually understanding what that information means. And I suspect that's where a lot of the real value in data science lives.

## Garbage In, Garbage Out. Or Slop In, Slop Out.

There's an old saying in computing: *Garbage in, garbage out.* Basically, if you feed a system bad information, you shouldn't be surprised when it produces bad results. With AI, I think we need an updated version. **Slop in, slop out.**

AI can produce some incredibly polished results from questionable information. Beautiful charts, detailed explanations, impressive-looking reports, and conclusions that sound completely reasonable. But a polished presentation doesn't make the underlying data accurate.

Imagine a company wants to understand why customer support tickets have declined. AI analyzes the numbers and determines that a new self-service knowledge base is responsible. Sounds great! The knowledge base is working, customers are finding answers, and the company is saving money.

Except maybe support tickets declined because the company lost customers. Or maybe the support team changed how tickets were categorized. Or maybe customers stopped submitting tickets because they were frustrated with the support experience. Same trend. Very different explanations.

If nobody questions the underlying data or challenges the conclusion, the company could end up celebrating something that isn't actually a success.

That's what interests me. Not just generating the analysis, but understanding whether the analysis tells us anything useful. And to be fair, AI can absolutely help identify these problems too. With the right context, instructions, and validation process, it can challenge assumptions and spot inconsistencies. But somebody still needs to know what questions should be asked and what information the system might be missing.

I want to be that person.

## So, Am I Still Going to Learn Python and SQL?

Yes. I'm not throwing the programming books out the window. Although I haven't bought any yet, so that would be a pretty uneventful protest.

I still want to learn Python, SQL, statistics, machine learning, and the fundamentals of data science. I just want to approach them differently. Rather than treating Python as the ultimate destination, I want to treat it as a tool that helps me understand and work with data.

I want to learn enough to read code, understand what it's doing, recognize problems, and make changes when necessary. I also want to understand the mathematics behind data science. Not because I have some sudden desire to become a mathematician, but because I don't want to blindly trust a statistical result simply because a computer generated it.

And I want to use AI throughout the process. I'm not going to pretend AI doesn't exist while I spend six months learning to do something it can already automate. That seems a little backward.

Instead, I want to see how much faster I can learn with AI while making sure I'm actually developing an understanding of the subject. There's a difference between using AI to learn something and using AI to avoid learning something. I suspect I'll have to remind myself of that quite often.

## My First Experiment: Can I Challenge AI's Analysis?

Rather than spending weeks writing about what I *think* AI can and can't do, I want to test some of these ideas. For my first experiment, I'm going to find a publicly available dataset and ask AI to analyze it. I'll give it a reasonably open-ended task and see what it comes back with.

Then I'm going to challenge its findings. I'll look at the data quality, question its assumptions, investigate the patterns it identifies, and try to determine whether its conclusions are actually supported by the evidence.

Of course, there's a slight catch. **I'm still learning data science myself.**

So there's a very real possibility that AI will be right and I'll be the one who completely misunderstands something. And that's fine! Actually, that's kind of the point.

I want to document what I understand, what confuses me, where AI helps, where it gets things wrong, and where I get things wrong. Maybe I'll discover that AI is better at identifying questionable data than I expected. Maybe I'll discover that I need a much stronger understanding of statistics before I can properly challenge anything. Either way, I'll learn something. And hopefully anyone reading along will too.
